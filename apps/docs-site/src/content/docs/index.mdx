## OwlLayer : des interfaces agentiques sous contrôle

**OwlLayer est un SDK d'AI-driven interfaces, ou interfaces agentiques.** Il permet à un agent IA d'agir dans une interface existante par des actions que le développeur déclare explicitement.

L'application conserve sa logique métier et ses garde-fous. L'agent reçoit seulement le contexte utile et les outils (`tools`) disponibles sur l'écran courant : il ne dispose pas d'un accès libre à l'interface.

## Le lien entre l'interface et le serveur

**AITP** (*Agent-to-Interface Transfer Protocol*) est le protocole d'échange de OwlLayer. Sur une connexion WebSocket, il transporte le contexte autorisé par l'application, les tools disponibles, les demandes d'exécution et leurs résultats entre `OwlLayerClient` et `OwlLayerServer`.

Le fonctionnement se résume à quatre étapes :

| Étape | Ce qui se passe |
| --- | --- |
| 1. Ouvrir la session | Le client s'authentifie auprès du serveur. |
| 2. Décrire l'écran courant | L'application envoie uniquement son contexte utile et ses outils actifs. |
| 3. Répondre ou demander une action | Le modèle peut produire une réponse ou demander l'exécution d'un outil déclaré. |
| 4. Exécuter sous contrôle | L'application exécute l'action autorisée ; le résultat revient au modèle puis à l'utilisateur. |

Si une action est sensible, le mécanisme **HITL** (*Human-in-the-Loop*) permet d'exiger une approbation humaine avant son exécution.
